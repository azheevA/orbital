# ORBITAL Explorer

Космическая обсерватория на Next.js App Router, TypeScript, React Three Fiber и модульной FSD-архитектуре. Главная страница содержит интерактивную модель Солнечной системы, а отдельный каталог `/catalog` — 19 объектов с индивидуальными научными досье.

## Требования

- Node.js 22.13+ (рекомендуется Node 22 LTS)
- npm 10+
- Доступ к интернету для установки пакетов, загрузки текстур и вызова NASA/JPL API
- Для комфортной работы с 3D-сценой рекомендуется современный браузер с WebGL 2

## Быстрый запуск

```bash
npm install
cp .env.example .env.local
npm run assets:download
npm run dev
```

Открой `http://localhost:3000`.

На Windows PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env.local
```

Для NASA API желательно получить персональный ключ на https://api.nasa.gov/ и вписать его в `NASA_API_KEY` в `.env.local`. `DEMO_KEY` оставлен как вариант для первоначальной проверки и имеет более строгие лимиты.

`ORBITAL_CONTACT_EMAIL` укажи как контактный адрес приложения. Он используется в User-Agent при обращении к JPL Horizons.

## Архитектура

```text
src/
├── app/                         # App Router, страницы, layouts, API routes
│   ├── catalog/                  # каталог и страницы объектов
│   └── api/astronomy/            # серверные HTTP endpoints
├── widgets/solar-system/         # композиция 3D-обсерватории
├── widgets/object-catalog/       # поиск, фильтры, карточки и досье
├── widgets/site-header/          # единая навигация
├── features/
│   ├── select-celestial-body/    # выбор планеты и JPL query
│   ├── focus-camera/             # фокусировка камеры
│   └── control-time/             # управление симуляцией
├── entities/celestial-body/      # планеты и орбитальная математика
├── entities/space-object/        # каталог звёзд, планет, спутников и галактик
├── shared/api/                   # общий HTTP-клиент
└── server/astronomy/             # NASA/JPL adapters
```

### Правила зависимостей

- `app` собирает виджеты и публикует Route Handlers.
- `widgets` композиционно объединяют `features` и `entities`.
- `features` реализуют пользовательские действия и состояние сценариев.
- `entities` хранят предметные модели и конфигурацию небесных тел.
- `shared` не знает о конкретных планетах, компонентах или страницах.
- `server` содержит внешние адаптеры; API-ключи и запросы к JPL/NASA не попадают в клиентский bundle.

Орбитальная математика находится в доменной сущности и не зависит от React, Three.js или Zustand. Это позволяет тестировать её отдельно. Слои направляют зависимости вниз: `widgets` могут использовать `features`, `entities` и `shared`; `features` — `entities` и `shared`; `entities` — только `shared`. `shared` не импортирует верхние слои.

## Источники данных

### JPL Horizons

`GET /api/astronomy/ephemeris?body=earth` получает гелиоцентрический вектор выбранного тела в AU относительно Солнца (`CENTER=500@10`, `EPHEM_TYPE=VECTORS`, плоскость ECLIPTIC). Запрос к JPL выполняется сервером, кэшируется на час и снабжается application-specific User-Agent. JPL просит не встраивать их API напрямую в браузер и повторно использовать кэшированные ответы.

Солнце и планеты выбираются непосредственно в 3D-сцене; двойное нажатие фокусирует камеру. Для 3D-подписей используются Canvas-native объекты `Text` из Drei; DOM-порталы `Html` намеренно не используются, чтобы не создавать вложенные React roots в React 19. Для небольших планет предусмотрены увеличенные невидимые зоны попадания.

Интерактивная сцена использует приближённые орбитальные элементы эпохи J2000.0 и уравнение Кеплера для плавного движения всех восьми планет. Радиусы орбит сжаты логарифмически, физические размеры тел условны. JPL-вектор показывается как отдельная live-проверка выбранного объекта; приложение не выдаёт модель за точную эфемериду всей системы.

### NASA NEO Feed

`GET /api/astronomy/neo` получает объекты, сближающиеся с Землёй, за текущую UTC-дату. Сервер нормализует данные и возвращает короткую сводку. Персональный `NASA_API_KEY` хранится только в `.env.local`.

## Каталог объектов

Каталог разделён на два режима: curated-коллекция ORBITAL и живые записи научных архивов. Данные загружаются по запросу, нормализуются на сервере и выдаются порциями; полные многомиллионные таблицы не скачиваются в браузер.

- `/catalog` — поиск по избранной коллекции и переключение на научные источники: NASA Exoplanet Archive, JPL Small-Body Database (астероиды/кометы) и CDS SIMBAD (звёзды/галактики/туманности/скопления).
- `/catalog/[slug]` — локальные редакционные досье для 19 избранных объектов.
- `/catalog/data?source=...&id=...` — динамическое досье для записи внешнего научного каталога.
- `GET /api/catalog/search` — серверная точка входа поиска. Параметры: `source`, `q`, `cursor`, `group`, `limit`. Ответ включает нормализованные записи, курсор следующей страницы, время загрузки и оценку количества, если первичный источник её сообщает.
- `GET /api/catalog/object` — получение актуальной записи внешнего источника по её идентификатору.
- `GET /api/catalog/media` — изображения для curated-коллекции. Для внешних записей `catalog.service.ts` вызывает общий поиск NASA Image and Video Library и прикрепляет изображения к результатам.
- Адаптеры источников расположены в `src/server/astronomy/`: `exoplanet-archive.adapter.ts`, `jpl-small-body.adapter.ts`, `simbad.adapter.ts`, `nasa-images.adapter.ts`. `tap-json.ts` нормализует и стандартный TAP-ответ `metadata/data`, и JSON-массив объектов, используемый Exoplanet Archive; `catalog.service.ts` объединяет научные записи с медиаданными.
- NASA Exoplanet Archive используется через таблицу `pscomppars` с параметрами планеты и звезды-хозяина; JPL SBDB Query API — для постраничного списка малых тел, а SBDB API — для получения подробного досье по SPK-ID или обозначению.
- SIMBAD TAP используется как широкая база идентификации и классификации глубококосмических объектов. Это мета-компиляция научной литературы, а не единый физический каталог: набор параметров неоднороден, поэтому записи всегда сохраняют ссылку на первоисточник. Поиск работает и по основному имени, и по альтернативным идентификаторам.
- Изображения NASA могут быть фотографиями миссий или художественными концептами. Экзопланеты помечаются как концепты; для остальных объектов тип изображения определяется по метаданным NASA. Если подходящего снимка нет, остаётся процедурная иллюстрация с явной пометкой.
- Численные параметры показываются вместе с единицами измерения из источника. Приложение не заполняет отсутствующие значения нулями и не выдаёт локальные оценки за измерения. Каждое досье содержит ссылку на первоисточник.
- Для TAP-запросов и SBDB не требуется `NASA_API_KEY`; ключ остаётся нужен для NASA NEO Feed и других API, где это предусмотрено. Изображения NASA Image and Video Library также не требуют ключа.
- Gaia DR3 и тематические каталоги VizieR оставлены для следующего этапа: Gaia даст крупную астрофизическую выборку звёзд, а VizieR — доступ к специализированным опубликованным каталогам. Их лучше подключать отдельными адаптерами с явным выбором каталога и схемы, а не превращать SIMBAD в универсальный источник всех измерений.
- Иконка сайта — `src/app/icon.svg`; Next.js использует её как favicon.

## Текстуры и лицензии

`npm run assets:download` скачивает карты Солнца и восьми планет, облачный слой Земли и кольца Сатурна. Источник — Solar System Scope, CC BY 4.0. Подробная атрибуция и важные ограничения текстур указаны в `public/textures/README.md`. Изображения не включены в исходный архив, чтобы сохранить небольшой размер поставки. Если текстуры не скачаны, сцена использует цветовые материалы-запасные варианты.

## Ограничения первой инженерной итерации

- Анимация использует усреднённые орбитальные элементы и учебную шкалу расстояний, а не точный интегратор N-body.
- JPL Horizons вызывается для выбранной планеты; автоматическая загрузка векторов всех планет намеренно не запускается, чтобы не создавать лишнюю нагрузку на сервис.
- NASA NEO Feed может вернуть ограниченный набор данных или HTTP 429 при превышении лимитов. `DEMO_KEY` имеет более строгие лимиты; для постоянного использования настрой собственный ключ.
- Авторизация, сохранение пользовательских экспедиций и база данных пока не входят в первую итерацию.

## Устранение React Html / removeChild предупреждений

В актуальной версии 3D-сцены нет компонентов `Html` из Drei. Подписи планет и Солнца рендерятся через `Text` непосредственно в WebGL-сцене. Это исключает создание вложенных React DOM roots, из-за которых React 19 + Drei `Html` могли выдавать `Attempted to synchronously unmount a root while React was already rendering`, а затем `NotFoundError: removeChild` при повторном создании корня.

Если после обновления исходников Next.js продолжает показывать старый stack trace с `Html`, останови dev-сервер, удали кэш `.next` и запусти приложение заново:

```powershell
# остановить npm run dev через Ctrl+C
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
npm run dev
```

Проверь, что в `src/widgets/solar-system/ui/solar-system-scene.tsx` импортируются `Line`, `OrbitControls`, `Stars`, `Text`, но не `Html`.

## TypeScript catalog fixes

Публичный API `entities/space-object` явно экспортирует типы научного каталога, категории `asteroid` / `nebula` / `cluster` и типы NASA media. `widgets/object-catalog` явно экспортирует `CatalogDataDetail`. Диспетчер источников каталога использует исчерпывающую проверку `never`, а параметры поиска JPL приводятся к `Record<string, string>` до сборки URL.

Если после обновления проекта TypeScript продолжает сообщать, что эти экспорты отсутствуют, проверь содержимое `src/entities/space-object/index.ts` и `src/widgets/object-catalog/index.ts`: локальная копия должна совпадать с актуальными barrel-файлами архива. После обновления останови dev-сервер, удали `.next` и `tsconfig.tsbuildinfo`, затем повтори:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
Remove-Item -Force tsconfig.tsbuildinfo -ErrorAction SilentlyContinue
bun run typecheck
bun run test
```
